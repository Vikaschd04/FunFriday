# Design feature $ARGUMENTS

Read `docs/DESIGN_SYSTEM.md`, `docs/USER_JOURNEYS.md`, and the feature-specific PRD only.

1. Define the primary user intent, user roles, emotional tone, success signal and critical states.
2. Have `product-designer` specify hierarchy, typography, reusable components, original visual motif, motion duration and reduced-motion alternative.
3. Present wireframe-level flow and a crisp component/state matrix. Avoid generic dashboard styling.
4. Have `frontend-engineer` implement accessible responsive UI against real contracts (when backend exists). Keep fake data visibly marked demo-only.
5. Test mobile 320px/tablet/desktop, keyboard, focus, error/empty/reconnect and motion preferences.
6. Summarize screenshots/observations if performed; never claim visual verification from source code alone.
