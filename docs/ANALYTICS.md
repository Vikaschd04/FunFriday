# Product Analytics and Success Measures

## North star

**30-day voluntary repeat-team usage:** percent of teams that host a second completed event within 30 days of their first. Compare across pilot cohorts, but avoid judgments about individuals.

## Funnel

Event created -> invitation delivered -> RSVP -> join -> active participation -> completed session -> optional enjoyment feedback -> second event.

## Metrics

| Metric | Definition |
| --- | --- |
| Event creation time | Host time from create CTA to valid saved event |
| Invitation delivery | Percent sent successfully through configured provider |
| Join success | Authorized joins / valid join attempts |
| Participation | Session-level, non-personnel aggregate gameplay completions |
| Completion | Completed sessions / started sessions |
| Enjoyment | Optional anonymous 1-5 post-session rating |
| Connection outcome | Voluntary statement: "I feel more comfortable talking to teammates" (aggregate only) |
| Repeat sessions | Teams with >1 completed session in 30 days |
| Realtime health | Disconnect rate, action ack latency, state mismatch incidents |

## Telemetry policy

Never create "least social employee" leaderboards, analyze employee mood at individual level, infer personality/mental health or reveal private Who Am I facts to admins. Retain only the minimum analytics needed. Use small-n suppression, aggregation and clear notice/consent where necessary.

## Pilot design

Recruit three team types: new-team onboarding, established remote team and cross-functional group. Rotate short/medium sessions. Collect organizer prep time, opt-in enjoyment, preferred game types and comfort-after-session feedback. Treat results as directional without claiming causal proof from uncontrolled surveys.
